## 🔴 КРИТИЧНО (21 проблема)

*Блокеры production. Требуют исправления до запуска.*

### Архитектура

**A-C1. Отсутствие платёжной интеграции**
- **Где:** `apps/mobile/lib/features/cart/checkout_screen.dart`, `apps/api/src/orders/`
- **Суть:** Опция «Онлайн» в checkout — просто строка, отправляемая на сервер. Нет SDK (YooKassa, CloudPayments, Stripe), нет webhook'ов, нет обработки платежей.
- **Влияние:** Клиенты видят работающую опцию, но оплата не проходит. Revenue loss = 100% онлайн-заказов.
- **Трудозатраты:** 40-60 часов (интеграция + тесты + webhook + возвраты)

**A-C2. Дублирование кода между mobile и courier**
- **Где:** `apps/mobile/` и `apps/courier/`
- **Суть:** Нет общего Dart-кода. ApiClient, Order model, AuthNotifier, темы, строки статусов — всё дублируется с разной реализацией.
- **Влияние:** Баг-фиксы требуют двойной работы. Статусы заказов различаются (mobile: `pending/confirmed/preparing`, courier: `NEW/CONFIRMED/COOKING`).
- **Трудозатраты:** 20-30 часов (создание `packages/mobile_shared/`, рефакторинг)

**A-C3. Разные enum'ы статусов заказов**
- **Где:** `apps/mobile/lib/core/models/order.dart`, `apps/courier/lib/core/models/order.dart`, `apps/api/prisma/schema.prisma`, `packages/shared/src/constants.ts`
- **Суть:** 
  - Backend: `NEW, CONFIRMED, COOKING, DELIVERING, READY_FOR_PICKUP, COMPLETED, CANCELLED` (7)
  - Mobile: `pending, confirmed, preparing, delivering, completed, cancelled` (6, другие имена)
  - Courier: `NEW, CONFIRMED, COOKING, READY_FOR_PICKUP, DELIVERING, COMPLETED, CANCELLED` (7, но `READY_FOR_PICKUP` вместо `DELIVERING` в некоторых местах)
- **Влияние:** Рассинхронизация статусов между приложениями. Клиент видит «preparing», курьер — «COOKING».
- **Трудозатраты:** 8-12 часов (унификация + миграция)

**A-C4. `/menu` использует локальные данные**
- **Где:** `apps/web/app/menu/page.tsx`, `apps/web/lib/catalog.ts`
- **Суть:** Страница `/menu` загружает данные из `lib/catalog.ts` (хардкод 5 категорий, ~30 товаров), не обращается к API. Главная страница использует API с fallback на этот же файл.
- **Влияние:** Клиенты видят устаревшее меню. Новые товары/цены не отображаются.
- **Трудозатраты:** 4-6 часов (переписать на API-запросы)

### Баги

**B-C1. `mobile.service.ts:466` — некорректная проверка владельца заказа**
- **Где:** `apps/api/src/mobile/mobile.service.ts:466`
- **Суть:** `order.customerName !== userId` — сравнивает имя клиента (строка) с userId (cuid). Всегда true. Должно быть `order.userId !== userId`.
- **Влияние:** Любой авторизованный пользователь может получить детали чужого заказа через mobile API.
- **Трудозатраты:** 1 час (фикс + тест)

**B-C2. `OrdersService.statusLabel` — dead labels**
- **Где:** `apps/api/src/orders/orders.service.ts`
- **Суть:** `statusLabel` ссылается на 8 статусов (`PREPARING`, `READY`, `DELIVERED`), но в enum `OrderStatus` только 7 значений. Эти label'ы никогда не используются.
- **Влияние:** Путаница при отладке. Push-уведомления могут показывать некорректные тексты.
- **Трудозатраты:** 2 часа (синхронизация с enum)

**B-C3. `/social/tg` показывает «Страница не найдена»**
- **Где:** `apps/web/app/social/[network]/page.tsx`
- **Суть:** Компонент обрабатывает только `vk` и `max` в switch-case. `tg` попадает в default → «Страница не найдена».
- **Влияние:** Пользователи, переходящие по ссылке Telegram, видят ошибку.
- **Трудозатраты:** 1 час (добавить case для `tg`)

### Безопасность

**S-C1. Хардкод-пароли в 76 Python-скриптах**
- **Где:** Корень репозитория (`deploy.py`, `check_smtp.py`, `test_vps.py` и др.)
- **Суть:** Все скрипты содержат plaintext-пароль VPS (`paramiko` → `212.119.42.249` root). Любой с доступом к репо имеет root-доступ к production-серверу.
- **Влияние:** **Критическая уязвимость.** Утечка репо = полный компромет production.
- **Трудозатраты:** 8-12 часов (перенос в `scripts/vps/`, чтение из env/SSH key)

**S-C2. CSP `'unsafe-inline'` для скриптов**
- **Где:** `apps/api/src/main.ts:78`
- **Суть:** Helmet CSP разрешает `'unsafe-inline'` для скриптов (Next.js требует). TODO P2: nonce-based CSP.
- **Влияние:** XSS-атаки могут инжектить произвольный JavaScript.
- **Трудозатраты:** 16-24 часа (nonce-generation, middleware, тесты)

**S-C3. CSRF-проверка только Content-Type**
- **Где:** `apps/api/src/main.ts` (CSRF middleware)
- **Суть:** Проверяет только `Content-Type` (JSON/multipart/form-data), не origin/referer. Обход через `multipart/form-data` с другого домена.
- **Влияние:** CSRF-атаки на staff-операции (смена статусов, назначение курьеров).
- **Трудозатраты:** 6-8 часов (добавить origin-check + CSRF-токены)

**S-C4. Access-токены в localStorage**
- **Где:** `apps/web/lib/auth-context.tsx`, `apps/web/lib/staff-auth-context.tsx`
- **Суть:** Client access-токены хранятся в `localStorage` (уязвимость к XSS). Staff access-токен — httpOnly cookie (безопасно), но refresh-токен тоже в `localStorage`.
- **Влияние:** XSS-атака → кража токенов → полный доступ к аккаунту.
- **Трудозатраты:** 12-16 часов (перевести client access в httpOnly cookie, как staff)

**S-C5. WebSocket gateway'и без аутентификации**
- **Где:** `apps/api/src/orders/orders.gateway.ts`, `mobile.gateway.ts`, `call.gateway.ts`
- **Суть:** 3 из 5 gateway'ев открыты (CORS `*`). Аутентификация только на уровне событий, не на connect.
- **Влияние:** Любой может подключиться к `/staff` и получать все заказы в реальном времени.
- **Трудозатраты:** 8-12 часов (JWT-проверка на connect, middleware)

**S-C6. Брутфорс OTP без экспоненциальной задержки**
- **Где:** `apps/api/src/social-auth/social-auth.service.ts`, `apps/api/src/mobile/mobile.service.ts`
- **Суть:** 6-digit код, 10 попыток (`attempts` field), но нет экспоненциальной задержки между попытками.
- **Влияние:** Злоумышленник может перебрать 10^6 кодов за ~1000 запросов (rate-limit 10/min → 100 минут).
- **Трудозатраты:** 4-6 часов (exponential backoff + IP-based rate-limit)

**S-C7. `.env.production` может содержать реальные секреты**
- **Где:** `.env.production` (корень репозитория)
- **Суть:** Файл может содержать реальные JWT-секреты, `YANDEX_CLIENT_SECRET`, `TELEGRAM_BOT_TOKEN`. Если в git — утечка.
- **Влияние:** Компромет всех OAuth-интеграций, подделка JWT-токенов.
- **Трудозатраты:** 2-4 часа (проверить `.gitignore`, переместить в Vault/SOPS)

### UX

**U-C1. Phone OTP отправляется на email**
- **Где:** `apps/api/src/mobile/mobile.service.ts:296`, `apps/web/components/auth-modal.tsx`
- **Суть:** Пользователь вводит телефон, ожидает SMS, но код приходит на email. UI показывает «Введите код из SMS».
- **Влияние:** Пользователи не находят код, уходят с сайта. Конверсия падает.
- **Трудозатраты:** 16-24 часа (интеграция SMS.ru + тесты)

**U-C2. Курьерская навигация — stub**
- **Где:** `apps/courier/lib/screens/courier_map_screen.dart:301-303`
- **Суть:** Кнопка «Проложить» показывает snackbar «Функция откроется во внешнем навигаторе». Нет `url_launcher`.
- **Влияние:** Курьеры не могут проложить маршрут из приложения. Переключаются на внешний навигатор вручную.
- **Трудозатраты:** 4-6 часов (интеграция `url_launcher` + deep-link в Яндекс.Навигатор/2ГИС)

### Производительность

**P-C1. Нет SSR/SSG для публичных страниц**
- **Где:** `apps/web/app/page.tsx`, `apps/web/app/menu/page.tsx`, `apps/web/app/about/page.tsx`
- **Суть:** Все страницы `'use client'`. Нет Server-Side Rendering / Static Site Generation. LCP > 2 секунд (целевой ≤ 2с).
- **Влияние:** Плохой SEO (Google не индексирует клиентский JS), медленная загрузка на слабых устройствах.
- **Трудозатраты:** 20-30 часов (переписать публичные страницы как Server Components)

**P-C2. Нет пагинации в CRM**
- **Где:** `apps/web/app/admin/orders/page.tsx`, `apps/web/app/admin/catalog/page.tsx`
- **Суть:** Списки заказов и товаров загружаются полностью. При >1000 записей — тормоза.
- **Влияние:** CRM зависает при большом количестве заказов. Операторы не могут работать.
- **Трудозатраты:** 12-16 часов (backend pagination + frontend infinite scroll)

### Масштабирование

**SC-C1. Single-node архитектура**
- **Где:** `infra/docker-compose.prod.yml`
- **Суть:** Один VPS, один postgres, один api, один web. Нет репликации, нет load balancing.
- **Влияние:** Single point of failure. При падении VPS — полный downtime.
- **Трудозатраты:** 40-60 часов (read replica, load balancer, health-checks)

**SC-C2. Нет автоматического backup PostgreSQL**
- **Где:** Инфраструктура
- **Суть:** Нет `pg_dump` cron, нет offsite storage, нет test restore.
- **Влияние:** При database corruption — полная потеря данных. RPO = ∞.
- **Трудозатраты:** 8-12 часов (cron + S3 + test restore script)

**SC-C3. Нет CDN для статических файлов**
- **Где:** `apps/api/src/main.ts` (express.static), `infra/nginx/`
- **Суть:** Uploads и images отдаются напрямую с VPS. Нет CDN (Cloudflare, Yandex CDN).
- **Влияние:** Высокая нагрузка на VPS при большом трафике. Медленная загрузка изображений из других регионов.
- **Трудозатраты:** 12-16 часов (настройка CDN + rewrite URL'ов)

### Архитектура

**A-I1. Нет cron-задач для очистки данных**
- **Где:** `apps/api/`
- **Суть:** Нет автоочистки истёкших OTP, refresh-токенов, деактивации акций по `endsAt`.
- **Влияние:** БД растёт бесконечно. Истёкшие токены могут быть использованы.

- **Влияние:** Неправильное назначение курьеров (всегда от кафе, не от адреса).

**A-I3. `proxy.ts` не редиректит неаутентифицированных пользователей**
- **Где:** `apps/web/proxy.ts`
- **Суть:** Проверяет наличие cookie `staff_token`, но не редиректит. Защита только на клиенте в `admin/layout.tsx`.
- **Влияние:** HTML-страницы `/admin/*` загружаются без аутентификации (серверные маршруты защищены, но это плохая практика).

- **Суть:** Все 38 `.tsx` файлов начинаются с `'use client'`. React Server Components не используются (кроме `layout.tsx`).
- **Влияние:** Потеря производительности RSC (меньше JS на клиенте, лучше SEO).
- **Трудозатраты:** 16-24 часа (рефакторинг публичных страниц)

**A-I5. Single `globals.css` (49 КБ)**
- **Где:** `apps/web/app/globals.css`
- **Суть:** Один файл на 522 строки. Нет CSS Modules, нет code-splitting стилей.
- **Влияние:** Весь CSS загружается на каждой странице. Медленная загрузка.

**A-I6. Операторское ПО — single-file HTML**
- **Где:** `apps/operator/renderer/index.html`
- **Суть:** Вся логика в одном HTML-файле. Нет TypeScript, нет сборки, нет компонентов.
- **Влияние:** Неподдерживаемый код. Трудно развивать.
- **Трудозатраты:** 40-60 часов (переписать на React/Vue + TypeScript)

**P-I2. Нет Redis-кэширования**
- **Где:** `apps/api/`
- **Суть:** Redis в `docker-compose.prod.yml`, но не используется в коде. Каталог, акции, меню — каждый раз из БД.
- **Влияние:** Высокая нагрузка на PostgreSQL.
- **Трудозатраты:** 12-16 часов (Redis integration + cache invalidation)

**P-I3. 5s polling fallback в admin chat**
- **Где:** `apps/web/app/admin/chat/page.tsx`
- **Суть:** Socket.IO + 5s polling fallback. При стабильном WebSocket polling не нужен.
- **Влияние:** Лишняя нагрузка на сервер (12 запросов/мин на каждого оператора).
- **Трудозатраты:** 4-6 часов (убрать polling, добавить reconnect logic)

**P-I4. Нет image optimization**
- **Где:** `apps/web/next.config.mjs` (`images: {}` пустой)
- **Суть:** Next.js Image Optimization не настроен. Изображения отдаются без ресайза/WebP.
- **Влияние:** Медленная загрузка изображений на мобильных (оригиналы 1-2 МБ).
- **Трудозатраты:** 6-8 часов (настройка `remotePatterns` + migration на `<Image>`)

### Масштабирование

**SC-I1. Нет connection pooling tuning**
- **Где:** `apps/api/prisma/prisma.service.ts`
- **Суть:** Prisma connection pool default (10 connections). При 100+ RPS — bottleneck.
- **Влияние:** Таймауты при высокой нагрузке.
- **Трудозатраты:** 2-4 часа (tuning + monitoring)

**SC-I2. Нет очереди для email**
- **Где:** `apps/api/src/email/email.service.ts`
- **Суть:** Nodemailer отправляет письма синхронно. При сбое SMTP — письмо теряется.
- **Влияние:** Потерянные письма (верификация, OTP, подтверждение заказа).
- **Трудозатраты:** 12-16 часов (BullMQ + retry logic + dead-letter queue)

**SC-I3. Нет rate-limit per-user**
- **Где:** `apps/api/src/app.module.ts` (ThrottlerModule)
- **Суть:** Throttler глобальный (3/20/100 за 1s/10s/60s), не привязан к userId/IP.
- **Влияние:** Один пользователь может исчерпать лимит для всех.
- **Трудозатраты:** 6-8 часов (custom Throttler + IP-based)

## 🟢 ЖЕЛАТЕЛЬНО (20 проблем)

*Средний приоритет. Улучшают качество, но не блокируют запуск.*

### Архитектура

**A-D1. Dev ≠ Prod compose divergence**
- **Где:** `infra/docker-compose.yml` vs `infra/docker-compose.prod.yml`
- **Суть:** Разные TLS-режимы, rate-limiting, мониторинг, Redis. Dev: HTTPS. Prod: HTTP-only.
- **Влияние:** «Работает на dev, падает на prod».
- **Трудозатраты:** 8-12 часов (унификация + override-файлы)

**A-D2. 76 Python-скриптов в корне**
- **Где:** Корень репозитория
- **Суть:** `deploy.py`, `check_smtp.py`, `test_vps.py` и др. Загромождают структуру.
- **Влияние:** Трудно найти нужный скрипт. Плохая организация.
- **Трудозатраты:** 4-6 часов (перенос в `scripts/vps/`)

**A-D3. Дублирование мапы статусов заказов**
- **Где:** `apps/web/app/cabinet/page.tsx`, `apps/web/app/admin/orders/page.tsx`
- **Суть:** TRANSITIONS map дублируется в двух файлах. Должно быть в `packages/shared`.
- **Влияние:** Рассинхронизация при изменении статусов.
- **Трудозатраты:** 2 часа (экспорт в shared)

**A-D4. Inline `style={{}}` в admin-страницах**
- **Где:** `apps/web/app/admin/**/*.tsx`
- **Суть:** Inline styles преобладают над CSS-классами.
- **Влияние:** Трудно поддерживать. Нет reuse.
- **Трудозатраты:** 8-12 часов (миграция на CSS-классы)

**A-D5. Нет API versioning strategy**
- **Где:** `apps/api/src/main.ts` (`setGlobalPrefix('api/v1')`)
- **Суть:** Только v1. Нет стратегии миграции на v2.
- **Влияние:** Breaking changes потребуют одновременного обновления всех клиентов.
- **Трудозатраты:** 8-12 часов (strategy doc + v2 scaffold)

### Баги

**B-D1. Codegen-зависимости объявлены, но не используются**
- **Где:** `apps/mobile/pubspec.yaml`, `apps/courier/pubspec.yaml`
- **Суть:** `freezed`, `json_serializable`, `build_runner` объявлены, но все модели hand-written.
- **Влияние:** Лишние зависимости. Путаница.
- **Трудозатраты:** 2 часа (удалить или начать использовать)

**B-D2. `go_router` объявлен, но используется `Navigator.pushNamed`**
- **Где:** `apps/courier/pubspec.yaml`, `apps/courier/lib/`
- **Суть:** `go_router` в dependencies, но навигация через `Navigator.pushNamed`.
- **Влияние:** Лишняя зависимость.
- **Трудозатраты:** 1 час (удалить из pubspec)

### Безопасность

**S-D1. Нет dependency scanning в CI**
- **Где:** `.github/workflows/ci.yml`
- **Суть:** Нет `npm audit` / Snyk / Trivy в CI.
- **Влияние:** Уязвимые зависимости попадают в production.

- **Суть:** Нет Application Performance Monitoring (Jaeger, Zipkin, DataDog).
- **Влияние:** Невозможно определить bottleneck.
- **Трудозатраты:** 16-24 часа (интеграция OpenTelemetry + Jaeger)

- **Суть:** Образы билдятся на VPS, не в CI. Нет приватного registry.
