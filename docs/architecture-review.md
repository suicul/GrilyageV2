## Резюме

Изменение **полностью соответствует архитектурным принципам** `AI_CTO.md` и roadmap. Устранена критическая IDOR-уязвимость (CVSS 7.5), убран лишний DB round-trip, добавлены unit-тесты. Однако выявлены две проблемы, требующие внимания перед мержем: неявное изменение API-контракта и отсутствие документации для guest-заказов.

**Итоговая оценка:** ✅ **Approve with minor improvements**

## 4. Безопасность

### 4.1. Устранённые уязвимости

| Уязвимость | CVSS | Статус | Комментарий |
|------------|------|--------|-------------|
| **IDOR (Insecure Direct Object Reference)** | 7.5 (High) | ✅ Устранена | `order.userId !== userId` корректно проверяет владение. |

**Детали:**
- **До:** `order.customerName !== userId` — всегда `true` (сравнение строки и cuid). Второй запрос `dbOrder.userId !== userId` работал, но первый чек был бессмысленным.
- **После:** `order.userId !== userId` — корректное сравнение двух cuid. Один запрос.

### 4.2. Новые риски

| Риск | CVSS | Статус | Комментарий |
|------|------|--------|-------------|
| **Утечка `userId` в ответе** | 3.7 (Low) | ⚠️ Требует исправления | `userId` теперь возвращается в ответе. Это внутренний UUID, не PII, но изменение API-контракта. |
| **Guest orders 401** | 0 (Info) | ℹ️ Документировать | Guest-заказы (`userId === null`) всегда возвращают 401. Это ожидаемое поведение, но не задокументировано. |

## 6. Рекомендации

### 6.1. Обязательные (до мержа)

1. **Убрать `userId` из ответа API**
   ```typescript
   const { userId: ownerId, ...orderWithoutUserId } = order;
   if (ownerId !== userId) throw new UnauthorizedException('Доступ запрещён');
   return orderWithoutUserId;
   ```
   **Причина:** Сохранение API-контракта, минимизация данных (§4 Compliance).

2. **Использовать enum в тестах**
   ```typescript
   import { OrderStatus } from '@prisma/client';
   // ...
   status: OrderStatus.NEW,
   ```
   **Причина:** Типобезопасность, соответствие §8.1 (DTO с class-validator).

### 6.2. Желательные

3. **Добавить тест на guest order**
   ```typescript
   it('should throw UnauthorizedException for guest order (userId is null)', async () => {
     mockPrisma.order.findUnique.mockResolvedValue({ ...sampleOrder, userId: null });
     await expect(
       service.getMyOrderById('user-1', 'ord-1'),
     ).rejects.toThrow(UnauthorizedException);
   });
   ```
   **Причина:** Покрытие edge case, документация поведения.

4. **Добавить inline-комментар**
   ```typescript
   // Guest orders (userId === null) are not accessible via this endpoint.
   if (order.userId !== userId) throw new UnauthorizedException('Доступ запрещён');
   ```
   **Причина:** Улучшение читаемости, документация для будущих разработчиков.

5. **Добавить audit logging** (отдельная задача)
   ```typescript
   this.logger.log('Order accessed', { userId, orderId });
   ```
   **Причина:** Соответствие §13 (логирование), compliance (152-ФЗ).

### 6.3. Будущие улучшения (отдельные задачи)

6. **E2E тесты для `GET /mobile/orders/:id`**
   - Покрытие критического user flow (просмотр заказа).
   - Соответствие §8.4 (E2E tests).

7. **Rate limiting для `getMyOrderById`**
   - Защита от enumeration attacks.
   - Соответствие §8.1 (429 Too Many Requests).

8. **Cache для `getMyOrderById`**
   - Redis caching (TTL 5 мин).
   - Соответствие §8.3 (caching).
